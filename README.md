# open-lifu-transmitter-bl

**Secure bootloader and secure firmware-update subsystem for the openLIFU transmitter (STM32L443).**

This is the immutable **Root of Trust** for each LIFU transmitter board. On every reset it verifies the
application firmware's authenticity (ECDSA P-256) and integrity (SHA-256) before launching it, and it
provides an authenticated firmware-update path over **USB** *and* over the inter-board **I²C** bus.
It is a port of ST's [X-CUBE-SBSFU](https://www.st.com/en/embedded-software/x-cube-sbsfu.html) v2.8.0
(SBSFU + Secure Engine) to the STM32L443, extended with a dual USB/I²C DFU transport and a one-wire
enumeration back-channel for the daisy-chained transmitter topology.

> ⚠️ **Development configuration.** This build runs with the STM32 hardware security IP **disabled**
> (`SECBOOT_DISABLE_SECURITY_IPS`) for debuggability. **Devices shipped for clinical use must be built
> and provisioned with RDP/WRP/PCROP/DAP-lock/MPU enabled** — see the production-hardening gate in
> [`docs/CYBERSECURITY_510k.md`](docs/CYBERSECURITY_510k.md) §12.

---

## Features

- **Secure boot (Root of Trust).** ECDSA-P256 header signature + SHA-256 firmware-body verification on
  every boot; fail-closed (invalid image is never executed → controlled recovery). Crypto scheme
  `SECBOOT_ECCDSA_WITH_AES128_CBC_SHA256`.
- **Dual-transport secure update (DFU).**
  - **USB DFU** (DfuSe) when a USB host is present.
  - **I²C DFU** when no USB host is present: an upstream board relays a signed image to a downstream
    board over I²C. The image is verified by the *target* board's secure boot before it can run — the
    relay is a transport, not a trust anchor.
- **Anti-rollback.** A signed 16-bit `FwVersion` plus a persistent monotonic **version floor** (flash
  page 126, outside the DFU-writable window). A validly-signed but older image is refused at boot and
  invalidated so it can never execute.
- **Phase 2 one-wire back-channel.** A bootloader-mode board joins the master's one-wire discovery and
  takes a **unique** I²C address (0x20, 0x21, …) instead of the fixed DFU address 0x72 — so two or more
  DFU-mode boards on the same bus don't collide and can each be programmed independently.
- **Resilience.** Boot-fail counter forces recovery DFU; IWDG watchdog; app-requested update via an
  RTC-backup magic + reset.

## Flash map (STM32L443, 256 KB / 2 KB pages)

Single source of truth: [`Core/Inc/memory_map.h`](Core/Inc/memory_map.h).

| Range | Size | Pages | Region | DFU access |
|-------|------|-------|--------|------------|
| `0x08000000`–`0x0800FFFF` | 64 K | 0–31 | Bootloader (SBSFU + Secure Engine) | read-only (immutable) |
| `0x08010000`–`0x0803EFFF` | 188 K | 32–125 | App slot 1 — header `@+0`, app `@+0x400` | **writable (signed only)** |
| `0x0803F000`–`0x0803F7FF` | 2 K | 126 | Anti-rollback version floor | read-only (bootloader-managed) |
| `0x0803F800`–`0x0803FFFF` | 2 K | 127 | User config | read-only (application-managed) |

The DFU writable window is clamped to the app slot, so **all** DFU-writable flash is covered by
secure-boot verification. DfuSe descriptor: `32*002Ka,94*002Kg,02*002Ka`.

## Build

Requires the `arm-none-eabi` GCC toolchain (15.x), CMake ≥ 3.22, and Ninja. The Secure Engine
(`SECoreBin`) is built and embedded automatically as part of the main build.

```bash
# Debug (verbose console trace on USART2 / COM5)
cmake --preset Debug -DDEBUG_ENABLED=ON
cmake --build build/Debug

# Release (silent — required for slave boards; enables the one-wire back-channel)
cmake --preset Release
cmake --build build/Release
```

Outputs land in `build/<preset>/open-lifu-transmitter-bl.{elf,hex,bin}`. VS Code build/flash/debug
tasks are provided in `.vscode/` (generated by `generate_vscode_files.py`).

> **Debug vs Release for slaves.** USART2/PA2 is the debug console in Debug builds *and* the one-wire
> CALL_IN back-channel in Release builds. Slave boards **must** run the Release bootloader (silent),
> otherwise trace output corrupts the back-channel. The master board may run either.

## Keys

The Secure Engine embeds the ECDSA **public** verification key and the AES-128 firmware key. The
generated key blob `SECoreBin/Startup/se_key.s` is **git-ignored** and must never be committed.

```bash
# Generate a key set (writes private material outside the repo; refreshes se_key.s + repo public key)
python py-tools/generate_keys.py            # add --force to overwrite
```

Private material (ECDSA private PEM, AES key) is kept **outside** the repo (resolved via `$LIFU_BL_KEYS`,
then `../bl-keys/transmitter`, then `py-tools/keys`). Only the ECDSA public key is retained in the repo.
The private signing key never resides on the device.

## Sign & flash the application firmware

Application firmware lives in the separate `openlifu-transmitter-fw` repo. Build it, then sign and
install a version at or above the anti-rollback floor:

```bash
# 1) Sign (FwVersion must be >= the device's persistent floor)
export LIFU_BL_KEYS=../bl-keys/transmitter
python py-tools/sign_firmware.py --firmware app.bin --version 3 --output app-signed.bin

# 2a) Install over USB DFU (host-connected board)
dfu-util -D app-signed.bin -a 0 -s 0x08010000:leave

# 2b) Install over I²C DFU (downstream board, relayed by the master)
python test/program_slave_i2c.py app-signed.bin --module 1
```

Flash the **bootloader itself** only via SWD (OpenOCD/ST-Link) or the STM32 ROM DFU — it is read-only
over the application DFU interface:

```bash
openocd -f interface/stlink.cfg -f target/stm32l4x.cfg \
  -c "program build/Release/open-lifu-transmitter-bl.hex verify reset exit"
```

## Testing

Host-side scripts (see `test/README.md`, `test/requirements.txt`):

- `test/program_slave_i2c.py` — program a downstream board over I²C DFU through the master.
- `test/test_phase2_enum.py` — verify Phase 2 enumeration (module modes, app vs bootloader, unique
  I²C addresses, DFU reachability at the assigned address).
- `test/dfu-i2c-test.py` — low-level I²C-DFU protocol exercise.

The `openlifu-sdk` package drives the master's USB VCP (`enumerate_modules`, `get_module_mode`,
`enter_dfu`, and `STM32I2CDFUviaMaster` for I²C-DFU-over-master).
